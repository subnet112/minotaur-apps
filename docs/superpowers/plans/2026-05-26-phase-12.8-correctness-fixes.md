### Task 2: Subagent C — abort, version, balance routing (F7, F8, F14, F15-out, error-body)

**Files:**
- Modify: `frontend/swap/src/hooks/useQuoteRequest.ts`
- Modify: `frontend/swap/src/hooks/useWalletBalances.ts`
- Modify: `frontend/swap/src/api/client.ts`

**Brief to give subagent:**

> Apply F7, F8, F14, F15-out, plus API error-body handling. Read the spec section "Open — 🔴 critical" in `docs/superpowers/specs/2026-05-26-phase-12.8-correctness-fixes-design.md` and the Q3 resolution.
>
> **F7 (AbortController):** Both `useQuoteRequest.ts` and `useWalletBalances.ts` perform `fetch`/`api.*` calls inside a `useEffect`. Add an `AbortController` per effect run; pass `controller.signal` into the fetch; abort the controller in the effect's cleanup. The `api/client.ts` methods used (`api.getQuote`, `api.getWalletBalances`) need to accept an optional `signal: AbortSignal` parameter and pass it to `fetch(..., { signal })`.
>
> **F8 (version counter):** In `useQuoteRequest.ts`, add a `useRef<number>(0)` request-version counter. Increment on each invocation; capture the local version; ignore the response (don't call `store.setQuote`) if the captured version is stale relative to the current ref.
>
> **F14 (Bittensor routing):** In `useWalletBalances.ts`, when computing `inputChainId`, force `0` if `store.walletMode === 'bittensor'`, regardless of `chainId`/`sourceChainId` UI selection. Same for the new output-balance call. Document the reason in a one-line comment: `// chain_id=0 routes to substrate path; 964 routes to EVM RPC. Force 0 for SS58 wallets.`
>
> **F15-out (cross-chain output balance):** Today `useWalletBalances.ts` force-nulls output balance when `isCrossChain`. Instead, issue a second `api.getWalletBalances(outputAddr, store.chainId)` call (the destination chain). `outputAddr` is `store.bittensorAddress` if `store.chainId === 0`, else `store.walletAddress`. Then `store.setOutputBalance(getBalance(store.outputToken))` from that response.
>
> **API error-body handling:** The validator API returns HTTP 200 with `{ "error": "..." }` on failures. In `api/client.ts`, `getWalletBalances` and `getQuote` should check `res.error` after `await res.json()` and throw if present so the caller's `.catch()` fires. In `useWalletBalances.ts` and `useQuoteRequest.ts`, the catch path should set `store.error` and call `toast.error({ title: 'Balance unavailable', message: err.message })` / `'Quote unavailable'`.
>
> Add at least one unit test per fix as inline checks in the existing test files where appropriate (the full hook test suite is H3 + H4's responsibility — don't write the full suites here; just regression guards).
>
> Commit message: `fix(swap): F7/F8/F14/F15-out — abort, version, balance routing + error-body`. No Claude trailer.
