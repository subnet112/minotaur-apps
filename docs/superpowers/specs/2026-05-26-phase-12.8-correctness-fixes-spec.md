## Open architectural questions

To resolve in the next session's brainstorm:

### Q1. Hook test strategy

- **MSW vs manual mocks?** MSW (Mock Service Worker) gives realistic HTTP interception; manual `vi.spyOn(api, 'getQuote')` is simpler but more brittle. Pick one and use it consistently.
- **`renderHook` vs full `render` with a thin wrapper component?** `@testing-library/react`'s `renderHook` is cleaner for pure hooks; `render` is needed for hooks that use React Router or context.
- **How to mock `window.ethereum`?** A global `vi.stubGlobal('ethereum', mockEthereum)` in `tests/unit/setup.ts`, with per-test override.
- **How to test the Zustand store interaction?** Reset store between tests via the existing `setState(initial, true)` pattern.

### Q2. Native-input flow (F21) — RESOLVED 2026-05-26

**Verdict: Contract does NOT support native ETH input. The frontend's `isNativeInput` flow is broken on-chain.**

Evidence (from F21 research subagent):
- `executeIntent` is not marked `payable` (inherited from `AppIntentBase`; the deploy script's line 10 comment explicitly flags this as a TODO).
- No `IWETH.deposit{value: ...}()` calls anywhere in `DexAggregatorApp.sol`.
- `msg.value == 0` guards at `DexAggregatorApp.sol:207, 291` skip fee processing when msg.value > 0 — fee handling was never designed for native input.
- `contracts/test/DexAggregator.t.sol` (1,449 lines) contains zero `{value: ...}()` calls. The native-input path was never tested.

Frontend implementation (`hooks/useOrderSubmission.ts`):
- Line 179 comment: "The contract wraps msg.value → WETH atomically inside _fundAndExecute" — this is incorrect.
- Lines 182-189 detect `isNativeInput` and set `_user_submit=true`.
- Lines 345-364 call `prepareDirectSubmit` API and submit TX with `{value: BigInt(prepared.value)}`.

User-visible failure mode:
1. User selects native ETH as input token.
2. ActionButton shows "Sign & broadcast" (per `selectActionState`).
3. User clicks → MetaMask popup with TX value.
4. User signs → TX reverts with "invalid callvalue" or similar.
5. MetaMask shows opaque "Transaction failed."
6. Funds are NOT lost (TX never executed) but no swap happens.

**Action (F21):** Remove the entire `isNativeInput` flow from the frontend. Users must wrap ETH → WETH manually (or via a future UI button) before swapping. Contract upgrade is out of scope for this phase — track as a separate issue against the `minotaur-apps` contracts directory.
