## Resolved open questions

### Q1 — Hook test strategy ✅
- **Mocking:** Direct `vi.spyOn(api, 'method')` + global `window.ethereum` stub in `tests/unit/setup.ts`. Skip MSW (overkill for this surface).
- **Rendering:** `renderHook` from `@testing-library/react`. Wrap hooks that call `useToast()` with a shared `HookWrapper` (`BrowserRouter` + `ToastProvider`) at `tests/unit/hooks/test-utils.ts`.
- **ethers v6:** `vi.mock('ethers', …)` at module level, mocks `BrowserProvider`, `id`, `keccak256`, etc.
- **@polkadot/api:** `vi.mock('@polkadot/api', …)` at module level.
- **Zustand reset:** adopt pattern from existing `tests/unit/store.test.ts` (snapshot initial state in `beforeAll`, restore in `beforeEach`).
- **Timers:** `vi.useFakeTimers()` per-test, not globally.
- **Fixtures:** `tests/unit/hooks/fixtures.ts` with `MOCK_TOKEN`, `MOCK_QUOTE`, `MOCK_ORDER`, mock account addresses.
- **Distribution:** ~165 tests total; `useOrderSubmission` (~45) and `useWalletConnection` (~35) are heaviest.

### Q2 — Native input flow (F21) ✅ (carried from prior session)
Contract does NOT support `msg.value`. Remove the frontend `isNativeInput` branch. Filter native ETH out of the input-token list when chain has a WETH alternative.

### Q3 — Balance API contract ✅ (empirical)
`GET /v1/wallets/{addr}/balances?chain_id={n}` routes by `chain_id`:
- `chain_id=0` → substrate path; accepts SS58, rejects hex.
- `chain_id≠0` → EVM RPC path; accepts hex, rejects SS58.
- API returns HTTP 200 even on errors; errors are in JSON body (`res.error`). Current hook silently treats errors as zero-balance.

**Fix:** route by `walletMode` (not by chain ID guess). If `walletMode === 'bittensor'`, force `chain_id=0` in `getWalletBalances` regardless of UI chain pick. Treat `res.error` as failure.

### Q4 — Coverage target ✅
Add `pnpm test:coverage` script using vitest's built-in v8 coverage. **Track but don't enforce** in CI. Numbers reported in PR.
